# 모듈식 AI 에이전트 시스템

이 폴더는 사용자가 보기 쉽고 기능끼리 섞이지 않도록 역할별로 분리한 새 기반이다.

```text
app/
├─ gateway/          공통 대화 처리와 채널별 어댑터
├─ orchestrator/     승인과 단계 상태 전환
├─ agents/           개발·설계, 독립 리뷰, 보완 정책
├─ contracts/        역할 사이의 데이터 인계 형식
├─ services/
│  ├─ budget/        토큰과 재시도 제한
│  ├─ context/       대화와 결정사항 범위 관리
│  ├─ logging/       비밀정보 제거 및 실행 기록
│  ├─ hermes/        ChatGPT OAuth를 쓰는 Hermes 실행
│  ├─ git/           저장소 위치·변경·로컬 커밋 보호
│  ├─ repository/    승인된 커밋 스냅샷의 제한적 읽기
│  └─ verification/  안전한 검증 명령 정책과 실행
├─ pipeline/         역할 순서, 작업 큐, 취소와 진행 알림
└─ storage/          SQLite 상태와 체크포인트
```

## 고정 개발 순서

1. 기반 구조
2. 공통 대화 게이트웨이 + 텔레그램 어댑터
3. 에이전트 파이프라인
4-A. 자유 대화 기반
4-B. 세 에이전트 자유 대화와 상호 호출
4-C. 실제 사용 안정화
5-A. 프로젝트·작업 상태 분리
5-B. 안전한 프로젝트 조회와 저장소 식별 승인
5-C. 자유 대화용 안전한 파일 검색·상세 코드 조회 도구
5-D. Telegram 전체 흐름 통합 테스트와 운영 안정화

## 현재 상태

- 1단계 기반 구조: 완료
- 2단계 공통 대화 게이트웨이: 완료
- 3단계 실제 에이전트 파이프라인: 완료
- 4-A 자유 대화 기반: 완료
- 4-B 세 에이전트 자유 대화: 완료
- 4-C 운영 안정화: 완료
- 5-A 프로젝트·작업 상태 분리: 완료
- 5-B 안전한 프로젝트 조회와 저장소 식별 승인: 완료
- 5-C 자유 대화용 안전한 파일 검색·상세 코드 조회 도구: 완료
- 5-D Telegram 전체 흐름 통합 테스트와 운영 안정화: 완료

Telegram 메시지는 공통 형식으로 바뀌므로 Discord, Slack, 웹 채팅, CLI 어댑터를 같은 핵심 로직에 연결할 수 있다. 자유 대화와 3단계 파이프라인은 채널과 분리되어 있어 새 채널을 추가해도 그대로 재사용한다.

5-D 통합 테스트는 Telegram 형식의 수신 메시지를 실제 게이트웨이·SQLite 대화/실행 큐에 넣고,
임시 로컬 Git 저장소에서 설계·승인·개발·리뷰·검증까지 실행한다. 승인 만료, 저장소 스냅샷
변경, 중지, 재시작, 중복 수신, 역할 실패, 토큰·재시도·감사 로그를 확인하며 원격 Git이나
GitHub push·PR은 호출하지 않는다.
