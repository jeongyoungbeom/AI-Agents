# 안전한 프로젝트 조회

자유대화 에이전트에는 파일 도구를 직접 열지 않는다. 이 계층이 사용자가 승인한 Git 저장소의 현재 커밋 `HEAD`를 요청마다 고정된 스냅샷으로 읽고, 크기가 제한된 구조와 관련 문서만 대화 문맥으로 전달한다.

초기 문맥만으로 답하기 어려우면 에이전트는 구조화된 읽기 전용 요청만 낼 수 있다.

- `search_files`: 안전한 파일의 상대경로와 UTF-8 텍스트 내용을 리터럴 문자열로 검색한다.
- `read_file`: 검색이나 트리에서 확인한 정확한 상대경로를 지정한 줄 범위로 읽는다.

게이트웨이가 요청 형식과 개수, 승인 상태, 저장소 식별값, 고정된 `HEAD`를 다시 확인한 뒤 이 계층을 호출한다. 도구 결과도 신뢰할 수 없는 저장소 데이터로 표시하고, 중간 모델 응답은 사용자에게 노출하지 않는다.

- 실제 Git 최상위 경로·공통 Git 디렉터리·최초 커밋·origin으로 저장소 식별값을 만든다.
- 승인 당시 식별값과 현재 값이 다르면 읽지 않고 재승인을 요구한다.
- `.git`, 환경파일, 인증정보, 개인키·인증서 형식은 기본 차단한다.
- 커밋된 파일만 `git show <현재 HEAD>`로 읽으므로 심볼릭 링크나 junction을 따라가지 않는다.
- 바이너리, 대용량 파일, 과도한 트리·문맥 크기를 제한한다.
- 내용은 비밀값 제거를 거치며 모델에는 신뢰할 수 없는 데이터라고 명시한다.
- 검색 결과 수·출력 byte와 상세 읽기 파일 크기·줄 수·전체 문맥 크기를 각각 제한한다. 파일 개수는 검색 중단 조건이 아니다.
- identity, 고정 HEAD, tree, 초기 문서 및 한 도구 batch는 각각 하나의 read-only Docker 컨테이너에서 처리한다. 선택 문서와 상세 읽기는 `git cat-file --batch`로 묶는다.
- 전체 안전 tracked file 검색은 고정 HEAD의 `git grep --fixed-strings -I`를 사용한다. binary·과대 파일·출력 제한·문맥 제한으로 빠진 결과와 잘림 사유는 구조화된 결과에 함께 표시한다.
- 상세 조회 전 `HEAD`가 바뀌면 이전 문맥과 섞지 않고 전체 도구 요청을 중단한다.
- Git 표준 출력과 오류 출력은 증분 수집하며 한도를 넘는 즉시 프로세스를 종료한다.
- 저장소 문맥의 상담은 현재 사용자 원문에서 허용한 대상만 안전한 목적·근거로 중개하고 원 요청자에게 반환한다. 저장소 지시에서 유래한 역할 호출·담당 이전·장기 기억 갱신은 차단한다.
- 장기 분석은 고정 commit manifest와 연속 행 조각을 사용한다. 큰 파일의 크기만으로 49KB에서 제외하지 않으며 blob 검증·실제 scan 상한·절대 행·미처리 범위를 보존한다.
- 부모 대화에 파일·줄·commit·비신뢰 출처를 누적한다. 같은 프로젝트의 후속 질문에서 근거를 이어받고 HEAD 변경은 과거 snapshot으로 표시한다.
